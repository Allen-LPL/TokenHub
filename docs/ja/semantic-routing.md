# Jev セマンティックルーティング

TokenHub は TypeSafe の Jev モデルを呼び出し、対象の Chat Completions リクエストに適した Provider と上流モデルを選択できます。Jev は独立した判断クライアントであり、TokenHub の Provider として登録する必要はありません。生成を実行するモデルには、有効なルートとリクエストのプロトコルをサポートする Provider アダプターが必要です。

## 動作

1. TokenHub は認証、利用枠の確認、プライバシー処理、安全性検査を実施します。レスポンスキャッシュに一致した場合、Jev を呼び出さずに返します。
2. プロジェクトと API Key の制限、スコープ付きポリシー、正常性、プロトコル互換性、優先度、基本アルゴリズムから候補順を生成します。
3. モデルとプロジェクトで機能が有効な場合、Jev は候補の能力情報とユーザーメッセージを受け取り、TypeSafe の `Choice` で候補または `no_preference` を返します。
4. `enforce` モードでは、有効な選択が信頼度の閾値を満たすと、対象の Provider とモデルを先頭に移動します。移動範囲は先頭のルート優先度とリソース優先度のグループ内です。その Provider とモデルの内部リソース順、および他候補の相対順を維持します。`shadow` は提案を記録するだけです。
5. 既存の実行・フェイルオーバー処理がその順序を使用します。Jev はリクエストごとに最大 1 回呼び出し、上流の失敗でも再評価・再試行しません。

既存の 6 種類の基本戦略は引き続き利用できます。厳密な主系・待機系の戦略では先頭優先度に通常 1 候補しかないため、Jev は呼び出されません。ルートシミュレーターは基本戦略を説明し、Jev を呼び出しません。

## 有効化とロールバック

初期状態では無効です。サーバー設定例：

```dotenv
TOKENHUB_SEMANTIC_ROUTING_ENABLED=true
TOKENHUB_SEMANTIC_ROUTING_PROJECTS=prj_example
TOKENHUB_TYPESAFE_API_KEY=<server-side-secret>
TOKENHUB_TYPESAFE_MODEL=jev-1.13.0
TOKENHUB_SEMANTIC_ROUTING_TIMEOUT_MS=1000
```

プロジェクト一覧は正確な ID のカンマ区切りです。空の一覧では外部呼び出しを許可せず、有効化時にキーや一覧がなければ起動検証に失敗します。評価モデルは具体的なバージョンを指定し、応答のバージョンが一致しなければ基本順序を維持します。タイムアウトはカタログ検索と評価を含み、不正な値や 10000 ms を超える値を拒否します。プロセスごとの同時 Jev 呼び出しは最大 8 件で、超過時は即座に基本順序を維持します。

「ルーティング → モデルルーティングポリシー → Jev スマートルーティング」で選択します。

- **無効**：評価やテキスト送信を行いません。
- **観察**（`shadow`）：評価と監査を行い、基本順序を維持します。
- **有効**（`enforce`）：有効な提案が閾値を満たすと順序を変更します。

初期閾値 `0.65` は評価の出発点であり、検証済みの品質保証ではありません。Jev の信頼度は選択肢の分布を示し、選択したモデルのタスク成功率ではありません。有効化前に、期待結果のある業務サンプルで観察結果を確認します。

モデル単位では「無効」を選択して戻せます。全体では `TOKENHUB_SEMANTIC_ROUTING_ENABLED=false` に設定して再起動します。ルートの削除や基本戦略の変更は行いません。

## 候補情報と公開モデルのエイリアス

Provider ID と上流モデルの組み合わせで候補をまとめ、同じリソースプールの複数アカウントを重複選択肢にしません。現在の公開モデルで許可済みのルートだけが対象です。Jev が Provider を追加したり、任意のモデルを選んだり、アクセス制限を回避したりすることはできません。

異なる生成モデルから選ぶには、`auto-chat` などの公開モデルエイリアスを明示的に作成し、承認済み上流モデルへルートを割り当てます。既存のモデル名に自動でルートは追加されません。公開モデルの既存の価格・課金ルールが適用され、選択した上流モデルに応じた自動再価格設定は行いません。

Jev に送る情報は Provider タイプ、上流モデル名、能力、入力モダリティ、対応パラメーター、および任意の `ProviderModel.metadata.routing_description` です。説明には評価済みのコードや翻訳能力など、検証可能な適性を記載します。認証情報、接続先、プロジェクト名、その他のメタデータ、価格、稼働状況は送りません。Jev にはブランド順位、ベンチマーク、価格を推測しないよう指示します。能力の根拠と業務評価がなければ、この機能だけで最適モデルを証明することはできません。

カタログに宣言されたテキストモダリティ、コンテキスト上限、パラメーター対応を制約に使います。カタログ項目のないモデルは昇格できません。能力宣言がないことは優位性の根拠になりません。候補情報が 2048 バイトを超える場合は除外し、Provider とモデルの組み合わせが 32 を超える場合は評価をスキップします。

## リクエスト範囲とデータ処理

初版はテキストのみの `/v1/chat/completions` とストリーミングに対応します。ツール、構造化出力の制約、マルチモーダル、推論の継続、セッション識別子、キャッシュアフィニティ、固定ルート、未知のリクエスト・メッセージフィールドはスキップします。Responses、Anthropic Messages、埋め込み、画像 API、ルートシミュレーションは従来の動作を維持します。

**観察**と**有効**の両方が、処理済みユーザーメッセージと限定した候補情報を `https://api.typesafe.ai/v1/systemone` に送信します。システム・開発者・アシスタントのメッセージ、ヘッダー、API Key、Provider 認証情報は送りません。ユーザーテキストは区切りを含めて 8192 バイト以内で、超過時は切り詰めずに基本順序を維持します。外部サービスへの送信を承認したプロジェクトだけを許可します。テキストと能力説明はデータとして扱い、ローカル検証で選択範囲を制限します。

タイムアウト、キャンセル、同時実行上限、レート制限、過負荷、不正・過大な応答、未知の選択、低信頼度、`no_preference` はすべて基本順序を維持します。リダイレクトには追従せず、TypeSafe 接続先は固定、認証はサーバー側で保持します。

監査イベントはアクション `routing.semantic` とゲートウェイリクエスト ID を使用します。モード、結果、プロンプト版、評価モデル版、信頼度、選択したローカルルート ID、評価 Token 数、判断時間を記録し、プロンプト、応答本文、認証情報は記録しません。評価 Token は生成モデルの利用量や顧客の請求には加算しません。TypeSafe 費用は別途予算化します。全体無効または許可外プロジェクトの場合、この監査イベントは生成しません。

## API 互換性

既存の `PATCH /api/admin/model-routing-policies/{model}` は、従来の `strategy` と完全な `routes` 一覧に加え、任意のフィールドを受け付けます。

```json
{
  "semantic_routing": {
    "mode": "shadow",
    "min_confidence": 0.65
  }
}
```

例は追加フィールドだけを示しています。実際の PATCH には基本戦略とすべてのルートが必要です。モードと明示的な有限の信頼度閾値（0〜1）は必須です。設定やルートが不正なら更新全体をロールバックします。旧クライアントが `semantic_routing` を省略した場合、保存済み設定を維持します。設定は `Model.metadata.tokenhub_semantic_routing` に保存し、新しいテーブルや移行は不要です。

## 検証と評価

自動テストは合成リクエスト、プロセス内 HTTP サーバー、模擬生成 Provider を使用します。TypeSafe プロトコル、候補制約、応答検証、モード、対象範囲、閾値境界、リソースプール、権限、キャンセル、タイムアウト、フェイルオーバー、原子的保存、画面の保存と再読み込みを検証します。実業務の精度や本番遅延を測定するものではありません。

まず**観察**で監査結果と追加遅延を確認し、承認済みの代表サンプルで成功率、生成費用、評価費用を測定してから、プロジェクトとモデルごとに有効化します。

仕様参照：[TypeSafe API](https://docs.typesafe.ai/api)、[Choice](https://docs.typesafe.ai/primitives/choice)、[Confidence](https://docs.typesafe.ai/confidence)。

任意の実 API プロトコルスモークテストは `TestJevRoutingClientLive` です。テストプロセスの環境だけに `TOKENHUB_LIVE_TYPESAFE_API_KEY` を設定し、`backend/` で `go test ./internal/server -run ^TestJevRoutingClientLive$ -count=1 -v` を実行します。TypeSafe に合成翻訳リクエストだけを送り、生成 Provider は呼び出しません。初期状態ではスキップします。

既存モデルのセマンティック設定はルーティングポリシー API が管理します。通常のモデル編集、古いメタデータの送信、起動時のカタログ更新は現在の設定を維持します。モデルとポリシーの更新はモデルを先にロックしてからルートを処理し、同時編集で古い外部送信設定が復元されることを防ぎます。
